# Семантичний пошук за науковими статтями в Pinecone

Проєкт порівнює пошук за цілими анотаціями та за їхніми фрагментами на підвибірці arXiv. Для векторів використано SPECTER2 Base. У Pinecone зберігаються вектори й метадані. Точне порівняння метрик і BM25 виконуються локально.

## Відтворення

Потрібен Python 3.12. Завантаж і розпакуй [корпус arXiv із Kaggle](https://www.kaggle.com/datasets/Cornell-University/arxiv). Усі команди нижче виконуються з кореня проєкту. Почати з кроку 03 можна, якщо залишилися Parquet із кроку 01 та всі файли кроку 02: `embeddings.npy`, `source_ids.json`, `encoded_ids.json` і `metadata.json` у папці `embeddings/`. Перший запуск моделі завантажує ваги з Hugging Face.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/01_prepare_data.py --input /шлях/до/arxiv-metadata-oai-snapshot.json
python scripts/02_embed.py
python scripts/03_load_to_pinecone.py
python scripts/04_search.py --as-of-year 2026
python scripts/05_chunking.py
python scripts/06_hybrid_search.py
```

Крок 01 читає перші 10 000 придатних статей і зберігає першу категорію та рік першої версії. Крок 02 зберігає матрицю, порядок ID та маніфест із хешами корпусу й векторів. Наступні скрипти перевіряють цю прив’язку. Щоб повторити підготовку за наявності файлів, можна передати новий шлях через `--output` у 01 і новий `--output-dir` у 02, а потім передати відповідні `--data` і `--embeddings-dir` у 03, 04 та 06. Параметр `--device cpu` доступний для кодування, а типово використовується доступний CUDA або MPS чи CPU.

Для хмарного прогону скопіюй `.env.example` до `.env` і задай ключ із виділеного проєкту Pinecone. Крок 03 створює `arxiv-papers` або перевіряє наявний індекс. Крок 05 окремо використовує `arxiv-chunks-fixed` і `arxiv-chunks-semantic`. Скрипти обирають простір імен за відбитком корпусу або набору чанків, тому повтор того самого набору оновлює ті самі ID. Передача `--backend pinecone` змінює призначення запитів і батчів на Pinecone.

```sh
python scripts/03_load_to_pinecone.py --backend pinecone
python scripts/04_search.py --backend pinecone --as-of-year 2026
python scripts/05_chunking.py --backend pinecone
python scripts/06_hybrid_search.py --backend pinecone
```

## Вибір бази, моделі та метрики

**Бази.** Pinecone є керованим комерційним сервісом. Для невеликої команди він зменшує роботу з обслуговування, але до затримки додається мережевий виклик, а пропускна здатність залежить від плану. Qdrant під Apache 2.0 можна розгорнути у своїй інфраструктурі або в керованій хмарі. Його варто розглянути, якщо дані мають залишатися у власній мережі або потрібно підбирати параметри HNSW і payload-фільтрації. Chroma під Apache 2.0 дає вбудований клієнт, власний сервер і Chroma Cloud. Локальний режим зручний для прототипу без мережевого виклику. Щоб порівняти продуктивність, потрібні однакові вектори й фільтри, той самий recall та вимірювання p95 затримки й пропускної здатності. [Pinecone](https://www.pinecone.io/pricing/) · [Qdrant](https://qdrant.tech/documentation/overview/) · [Chroma](https://docs.trychroma.com/docs/overview/introduction)

**Модель.** У картці SPECTER2 Base зазначено, що «The base model is trained on citation links between papers». Це навчання на зв’язках між науковими роботами. `all-MiniLM-L6-v2` є загальним 384-вимірним кодувальником речень і коротких абзаців. Для вправи використано зазначену в рубриці базову модель SPECTER2, 768 компонентів, до 512 токенів та CLS pooling з явним налаштуванням Sentence Transformers. Для загальних і спеціалізованих пошукових задач автори SPECTER2 також пропонують адаптери, тому результати базової моделі тут не є оцінкою варіанта з пошуковим адаптером. [SPECTER2 Base](https://huggingface.co/allenai/specter2_base) · [MiniLM](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) · [SciRepEval](https://aclanthology.org/2023.emnlp-main.338/)

**Метрика.** Картка Base пояснює підготовку `title [SEP] abstract`, CLS і вибір адаптера. Вона не встановлює універсальної метрики для цієї конфігурації. Індекс використовує cosine, оскільки в цій вправі і запити, і документи нормалізуються. Для ненульових одиничних векторів `cos(x,y) = (x·y) / (‖x‖‖y‖) = x·y`. Крім того, `‖x−y‖² = ‖x‖² + ‖y‖² − 2(x·y) = 2 − 2 cos(x,y)`. Тому спадний порядок cosine і dot збігається зі зростанням L2 для точного пошуку за однакових правил нічиїх. У наближених індексів кандидати можуть відрізнятися через алгоритм і налаштування. Без нормалізації dot також залежить від довжини вектора. Для запиту `(1,0)` вектор `(8,6)` має dot `8`, cosine `0,8` і квадрат L2 `85`, тоді як `(1,0)` має відповідно `1`, `1` і `0`. За dot перша точка стане вище, за cosine і L2 — друга.

## Метадані та фільтри

У `arxiv-papers` кожному рядку відповідає ID `paper_<номер>`. Метадані зберігають `arxiv_id`, заголовок, прев’ю анотації до 500 символів, авторів до 200 символів, рік і категорію. Ліміт Pinecone стосується сумарного розміру метаданих запису в байтах. Коротке прев’ю заощаджує місце й трафік. Модель отримує повну анотацію з Parquet в межах токенів моделі. Після пошуку повний текст доступний за `arxiv_id`. Якщо рік невідомий, поле пропускається й запис не потрапляє у фільтр за роком. [Ліміти Pinecone](https://docs.pinecone.io/reference/api/database-limits)

Пошукові запити та видачу наведено в результатах. Рік має числовий тип, категорія порівнюється з `cs.LG` як точний рядок. Для контрольної дати 2026 рік фільтр охоплює поточний і чотири попередні календарні роки, від 2022 до 2026 включно. Основна вибірка містить лише 2007 рік. Тому фільтр нових статей повертає нуль кандидатів, а умова «до 2015» охоплює всі 10 000. Окремий контрольний набір перевіряє, що фільтр працює і коли сучасні записи є. Із 50 статей 16 відповідають одночасно року та основній категорії. Першою для `reinforcement learning` у цьому контролі стала *Max-Entropy Reinforcement Learning with Flow Matching and A Case Study on LQR*. Підвибірка нових статей була цільовою, тому цей тест перевіряє логіку фільтра.

## Розбиття анотацій

Для 30 найдовших анотацій фіксована стратегія використовує до 100 слів і 20 слів перекриття. Стратегія за реченнями пакує повні речення до того самого ліміту. Якщо одне речення саме довше за весь бюджет, до нього застосовується фіксоване розбиття. Обидві стратегії покривають весь текст. Перекриття переносить частину контексту через межу, але за більшого перекриття зростає кількість записів, витрати на кодування й імовірність, що два перші результати належатимуть одній статті. Пакування речень може давати більше коротких чанків, якщо наступне речення не вміщується в залишок бюджету.

Під час запуску отримано 120 фіксованих і 121 чанк за реченнями. Усі 121 чанки другої стратегії починалися й закінчувалися на межах речень, визначених скриптом. У фіксованих чанків таких початків було 33 із 120, а кінців — 34 зі 120. На запит про фазові переходи обидві стратегії показали першою статтю `0705.1045`. Фіксований уривок починався з кінця попереднього речення, а уривок за реченнями одразу переходив до опису критичної точки. За двома запитами з машинного навчання першими були статті з астрофізики. На цій вибірці можна підтвердити кращу цілісність уривків за реченнями, а для висновку про релевантність потрібне окреме оцінювання.

За сталого розміру 100 слів перекриття 0, 20 та 40 слів дало відповідно 117, 120 і 150 чанків. Кількість повторених позицій слів становила 0, 1 800 і 4 800. Усі три конфігурації покривали текст повністю.

У 10–15 словах може залишитися назва методу без умови експерименту або результату. Чанк на 500+ слів може змішувати кілька тем і перевищити ліміт у 512 **токенів**. Доцільно порівнювати кілька розмірів на даних із відомими релевантними уривками й рахувати також повтори одного `arxiv_id` у top-5. Вплив overlap варто перевіряти за сталої довжини чанка, зіставляючи кількість записів і якість збігів біля межі фрагментів.

## Лексичний, семантичний і гібридний пошук

Векторний пошук варто перевіряти на перефразуваннях. BM25 допомагає, коли в запиті є точна назва, автор чи ідентифікатор і цей термін представлений у текстових полях індексу. Якщо корпус передує появі терміна, метод ранжування не може знайти відсутню статтю. RRF підсумовує `1/(k + rank)` для позицій від 1 і дає нульовий внесок за відсутності документа у списку. За меншого `k` перші місця мають більшу перевагу, а за більшого `k` стає помітнішою присутність документа в обох списках. За глибини 50 кандидатів документ із позиції нижче п’ятої може з’явитися в спільному top-5, навіть коли він відсутній в обох окремих top-5. [Стаття про RRF](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)

| Запит | Перше місце BM25 | Перше місце cosine | Перше місце RRF `k=60` |
| --- | --- | --- | --- |
| `BERT fine-tuning` | `0705.2241` | `0705.2404` | `0705.2241` |
| `Yann LeCun convolutional networks` | `0704.0282` | `0705.3171` | `0704.1144` |
| `making computers understand human emotions from text` | `0704.3665` | `0704.3665` | `0704.3665` |
| `prompt diphoton production at Tevatron` | `0704.0001` | `0704.0001` | `0704.0001` |

Для BERT збіг *fine tuning* стосується фізики, а не мовної моделі. Для запиту про емоції всі методи поставили першою статтю про введення тексту, що також є слабким збігом. Позитивний контроль про Tevatron повернув очікувану `0704.0001` у всіх трьох методах. Ці приклади показують дві різні причини слабкої видачі: потрібної статті немає у вибірці або система знаходить формально схожий текст на іншу тему. У трьох обов’язкових запитах до гібридного top-5 потрапили відповідно 1, 3 і 3 статті, яких не було в окремих top-5. Для запиту про LeCun зменшення `k` до 1 змінило перше місце на `0704.0282`, яке вже було першим у BM25.

## Pinecone Starter і 10 мільйонів статей

Таблиця Starter на 17 листопада 2026 року вказує до п’яти індексів, 100 просторів імен на індекс, регіон AWS `us-east-1`, до 2 ГБ зберігання й місячні квоти на читання та запис. Три індекси вправи вкладаються за кількістю, якщо у проєкті є вільні місця. Для 10 млн векторів по 768 компонентів `float32` лише значення займають `10 000 000 × 768 × 4 = 30 720 000 000` байтів, приблизно 30,72 ГБ без метаданих і службових структур. На такому масштабі варто оцінити керований тариф або власний кластер. Дані й індекс слід ділити за параметрами росту й фільтрації, обчислювати вектори пакетно та обирати ANN або квантування за фактичними recall, p95 затримки й вартістю.
